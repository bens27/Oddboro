- [staff] **Decision (2026-11-16): an Odd's chat session that reaches 120,000 tokens of context writes notes for itself before the next reply, and that reply starts a fresh session that opens with the notes, then the latest of the chat.** A long chat otherwise grows until its tool compacts it or runs out of room, and the Odd loses what it was doing. The office measures how full the session was at its last model call (Claude Code and Grok from each `assistant` line's usage, Codex from the last token count in its own session file; Gemini is not measured), so nothing runs on a loop. The notes run waits for the owner's next message rather than running after a reply, so the chat is never busy while the owner is free to write. One threshold serves every tool, below where Claude Code compacts on its own. The notes are the office's own file (`checkpoint.md`), never mailed or listed in Storage, and a persona never voices them. A notes run that fails keeps the session. Code in `apps/office/src/lib/server/chat-handoff.ts`; `apps/office/CLAUDE.md` describes it with the chat session.
